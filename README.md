# Fairy Comic Library

漫画アーカイブを整理・検索する、Ubuntu 向けのデスクトップアプリです。  

## 主な機能

- PDF、EPUB、AZW3、ZIP / CBZ、7z、RAR / CBR、MKV / MP4 のインポートとライブラリ管理
- SHA-256 による重複検出と、アーカイブからの表紙サムネイル生成
- PDFはページ数を取得し、先頭ページを表紙として使用（手動での表紙選択は非対応）
- EPUB / AZW3 は埋め込みカバーを使い、OSに関連付けられた電子書籍リーダーで開く
- お気に入り、作者・シリーズ・分類タグ、検索、絞り込み、並べ替え
- サムネイルの複数選択と、一括のお気に入り・タグ設定・管理対象外への移動・7z + AVIF 変換
- アーカイブを外部ビューアーで開き、読書履歴を記録
- 動画はOSに関連付けられたプレーヤーで開き、任意のパッケージ画像をサムネイルに設定
- リポジトリの検証、サムネイルの再作成、別の PC へ移行できるバックアップ
- ZIP / CBZ を 7z + AVIF に変換（非可逆変換。実行前に確認が表示されます）

## 動作環境

- Ubuntu x86_64
- Node.js 24 以降
- Rust stable 1.85 以降
- AppImage の実行には FUSE 2 互換ライブラリが必要です。Ubuntu 24.04 / 26.04 では `libfuse2t64` を使用してください（26.04 の標準 FUSE 3 だけでは足りません）。

開発環境のセットアップに必要な Linux システムパッケージは、[Tauri の Linux 前提条件](https://v2.tauri.app/start/prerequisites/#linux)を参照してください。

## 使い方

1. 配布された AppImage を実行します。
2. アプリ管理リポジトリの場所を選択するか、新しい空のディレクトリを選択します。
3. 「＋」ボタンまたはドラッグ＆ドロップでPDF、EPUB、AZW3、アーカイブまたはMKV / MP4動画を追加します。

ウィンドウ上部の「すべての作品」などのタイトル部分をドラッグすると、ウィンドウを移動できます。右上のボタンで最大化・元に戻す、または閉じる操作ができます。

PDFとアーカイブ、動画は選択したリポジトリへ移動します。漫画アーカイブは同梱の Brave Comic Reader で開き、EPUB / AZW3 と動画はOSに関連付けられたアプリで開きます。動画を開けない場合は、OS側で対応する動画プレーヤーを関連付けてください。

動画からサムネイルを自動生成することはありません。動画と同じフォルダから、拡張子を除くファイル名が同じ画像（PNG、WebP、JPEG、GIF、BMP）を一緒に選択またはドロップすると、その画像をサムネイルとして登録します。画像は動画と同じ名前のまま選択元に残ります。画像を指定しなかった場合は「サムネイル未指定」の固定画像を表示します。後から詳細パネルの「パッケージ画像を選ぶ」で設定・変更できます。対応画像が複数ある場合は自動選択せず、詳細パネルから指定してください。

動画の詳細パネルには、ファイルから取得した再生時間を表示します。再生時間が含まれていない場合や読み取りに失敗した場合は、その理由を表示します。

ファイル名の先頭には、`(分類)`・`[作者名]`・`{シリーズ名}` をそれぞれ複数指定できます（例: `(分類1)(分類2)[作者1][作者2]{シリーズ1}{シリーズ2} タイトル.zip`）。各指定は独立して読み取られ、タグ名は前後の空白を除いて1〜100文字です。サムネイルカードでは有効なタグ表記をファイル名から表示上だけ除きます。

インポート中は元ファイルを読み取り専用の共有ロックで開きます。これは協調型ロックであり、他のアプリもロックを尊重する必要があります。元アーカイブの編集・置き換えはインポート中に行わないでください。重複確認には `sha256sum`、異なるファイルシステム間のコピーには `cp` を使います。同一ファイルシステムではコピーせず、元ファイルをハードリンクしてDB登録後に元の名前を削除します。

サムネイル一覧は独立してスクロールし、検索・並び替え欄とウィンドウ操作ボタンは常に表示されます。サムネイルをクリックして選択し、Ctrl/⌘+クリックで選択を追加・解除、Shift+クリックで範囲選択できます。詳細パネルから、単体または複数のアーカイブを管理対象外にしてダウンロードフォルダへ移動できます。この操作では管理リポジトリ内のアーカイブ情報とサムネイル、アーカイブへのタグ付けが削除され、他の作品で使われなくなったタグも整理されます。ダウンロードフォルダに同名ファイルがある場合は上書きせず、そのアーカイブの移動を中止します。複数選択時は、お気に入りやタグの一括設定もできます。選択した ZIP / CBZ は詳細パネルから順番に 7z + AVIF へ変換できます。

## 開発

依存パッケージをインストールし、開発モードで起動します。

```bash
npm ci
npm run tauri dev
```

開発起動時に、SVT-AV1を有効にした`avifenc`サイドカーとPDFium 8125ライブラリを用意します。初回はCMake、Git、NASM、libpng、dav1dの開発パッケージとネットワーク接続が必要です。PDFiumはSHA-256を検証して取得します。ビルド済みのサイドカーとライブラリは`src-tauri/target/`および`src-tauri/binaries/`に保持されます。

Rustバックエンドをデバッグするには、VS CodeにCodeLLDB拡張をインストールし、実行とデバッグで「Debug Tauri」を選んでF5を押します。必要なサイドカーとRustバックエンドのビルド、Vite開発サーバーの起動は自動で行われます。

Snap版VS CodeでWebKitが`libpthread.so.0`のシンボルエラーを出す場合は、代わりに「Debug Tauri (VS Code Snap)」を選択してください。Ubuntu x86_64のシステム側のライブラリを優先して起動します。デバッグ終了後もViteタスクは動作するため、ポート1420が使用中の場合は、VS Codeの該当ターミナルでCtrl+Cを押して停止してください。

フロントエンドの型チェックとビルドは次のコマンドで実行できます。

```bash
npm run build
```

## リリースビルド

アプリのバージョンは `package.json` の `version` を唯一の定義元とします。更新時は `npm version <新しい番号> --no-git-tag-version` を使うと、`package-lock.json` も同期されます。Tauri は設定から `package.json` を読み込みます。

```bash
npm run build:release
```

このコマンドは [Brave Comic Reader](https://github.com/takanemu/braveComicReader) の最新リリースから Linux x86_64 用ビューアーを取得し、チェックサムを検証してから AppImage をビルドします。GitHub へのネットワーク接続が必要です。
また、SVT-AV1 v4.2.0 と libavif v1.4.2 から `avifenc` サイドカーをビルドし、PDFiumライブラリとともにAppImageへ同梱します。変換時はRust側で画像をデコードして向きを補正し、一時PNGをSVT-AV1が対応する4:2:0形式でAVIFへエンコードします。

生成物は `src-tauri/target/release/bundle/appimage/` に出力されます。

## GitHub Actions

`v*` 形式のタグを push すると、GitHub Actions が Ubuntu 24.04 上でビューアーを取得・検証し、AppImage をビルドして GitHub Release に公開します。リリース前に `package.json` のバージョンを更新し、その値に対応するタグ（例: `v0.6.0`）を作成してください。

## アプリ管理リポジトリ

選択したディレクトリに、アーカイブ・サムネイル・SQLite データベースをまとめて保存します。バックアップもリポジトリ全体を対象とするため、別の PC ではコピー先を「場所を変更」から選び直して利用できます。

```text
<repository>/
├── repository.json
├── archives/
│   └── <ハッシュ先頭2文字>/
│       └── <元のファイル名>
├── thumbnails/
│   └── <ハッシュ先頭2文字>/
│       └── <SHA-256>.webp
└── database/
    └── library.sqlite3
```
